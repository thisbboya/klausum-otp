# Apple-style website, control room and AI assistant — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the hand-written `/admin` and `/dashboard` pages with an Apple-style React front-end (public website + control room), add a Fixes tab driven by a handbook, and a Gemini assistant whose risky actions need an Approve tap.

**Architecture:** `web/` is a Vite multi-page React app built to `web/dist`, served by the same Worker through Workers Static Assets; API paths run the Worker first. The handbook (`src/handbook.ts`) maps alert keys to explanations and actions; the assistant (`src/assistant.ts`) calls Gemini with function-calling tools that map 1:1 to admin actions, gated by a safe/approve split and logged to `ai_actions`.

**Tech Stack:** Cloudflare Workers + Hono + D1 (existing), Vite 6 + React 18 + TypeScript (new, `web/`), Gemini REST `generateContent` with function declarations, Vitest + `@cloudflare/vitest-plugin` (existing).

**Spec:** `docs/superpowers/specs/2026-11-17-apple-ui-design.md`

## Global Constraints
- Free tiers only; Workers free plan 10 ms CPU — no heavy work in the Worker; AI is an outbound fetch.
- One repo, one Worker, one CI pipeline (`.github/workflows/deploy.yml` builds `web/` before deploy).
- Strict CSP on every page: no inline scripts. API responses keep `default-src 'none'`.
- Login unchanged: email code + authenticator → `__Host-kotp_admin` session; assistant endpoints are session-or-token admin routes.
- AI may act alone only on: `block_add` (kind ip|phone|email|domain) and `provider_order` (move a failing email provider later). Everything else returns `pending_approval`.
- AI never receives codes, recipients, key values or secrets — only stats, logs (no recipients), app metadata, handbook.
- No AI/tool credits anywhere (commits, UI, docs). Commit author: `Sadick <noreply@klausum.study>`, plain messages.
- Apple look: system font stack `-apple-system, BlinkMacSystemFont, "SF Pro Text", "Segoe UI", Roboto, sans-serif`; bg `#f5f5f7` / dark `#000`; cards `#fff` / dark `#1c1c1e`; radius 12–20 px; accent `#0a84ff`; translucent sticky header (`backdrop-filter: saturate(180%) blur(20px)`); motion 200–300 ms ease-out, off under `prefers-reduced-motion`.

## Review Focus
- Gemini key missing → Assistant tab says "Add GEMINI_API_KEY to switch the assistant on" (no crash); Fixes still work without AI.
- Gemini returns a tool call for an unknown/unsafe tool → never executed; reply shows it as a pending suggestion only.
- Session expires mid-chat → UI returns to the login card, chat text kept in memory.
- Page refresh on a deep link like `/admin#logs` → opens that tab.
- Phone width 375 px → no horizontal scroll on any screen.

### Task 4: Assistant backend (Gemini + gated tools + audit)

**Files:** Create `src/assistant.ts`, `migrations/0010_ai_actions.sql`, Modify `src/admin.ts`, `src/index.ts` (Env `GEMINI_API_KEY?`, `GEMINI_MODEL?` default `gemini-2.5-flash`), `src/monitor.ts` (diagnosis hook), Test `test/assistant.test.ts`

**Interfaces:**
- `type ToolName = "get_stats"|"get_logs"|"list_apps"|"get_fixes"|"block_add"|"block_remove"|"provider_order"|"provider_toggle"|"app_pause"|"app_resume"|"app_cap"|"key_rotate"|"key_revoke"|"run_check"`
- `SAFE_TOOLS = new Set(["get_stats","get_logs","list_apps","get_fixes","run_check","block_add","provider_order"])` (reads + two protective writes).
- `runTool(env, name, args): Promise<unknown>` — executes via the same DB logic as admin routes.
- `POST /admin/assistant` body `{ messages: {role:"user"|"model", text:string}[] }` → `{ reply: string, actions: { id, tool, args, status: "done"|"pending_approval", result? }[] }`
- `POST /admin/assistant/approve` `{ id }` → runs a pending action, marks it `approved`; `POST /admin/assistant/cancel` `{ id }`.
- `GET /admin/assistant/actions` → last 50 from `ai_actions(id, created_at, tool, args_json, status, result_json, source)`.
- `diagnose(env, alerts): Promise<string|null>` used by `selfCheck` for new alerts; stored in `settings` key `ai_diagnosis:<alertKey>`, appended to the Telegram/email alert.
